# 切换页面与后台回答

回答生成由 Web 进程中的独立 ASGI 任务执行，SSE 连接只订阅显示内容。页面切换、刷新或关闭连接不再取消生成；点击“停止回答”通过带 CSRF 校验的 POST 接口取消任务。删除会话也会停止其任务。

首页和检索页在当前标签页的 sessionStorage 中按用户保存会话标识。返回时通过原历史接口读取数据库快照：生成期间每两秒更新，完成后停止轮询。网络读取失败可重试，登录失效、无权限或会话删除不无限重试。关闭整个标签页后可以从会话历史重新打开。

## 数据与接口

- Message.completion_status 增加 queued、running，已有 complete、incomplete 保留。
- 0025 迁移以数据库唯一约束保证同一会话只有一个排队或执行中的回答；重复 POST 返回 409，不追加重复用户消息。
- 当前进程只允许一个回答执行，其余任务排队。生成正文和引用按原逻辑写入数据库；增强模式只保存核对后发布的内容。
- `GET /kb/conv/<thread_id>/messages/` 追加 active_answer（标识、阶段、耗时）；已有消息字段不变。
- `POST /kb/conv/<thread_id>/stop/` 要求登录、会话所有权、知识库权限和 CSRF。后台停止与断开页面显示连接是两种独立操作。
- SSE 使用有界回放缓存；慢客户端落后超过缓存后需要从数据库恢复，不阻塞生成任务。

## 运行范围

本实现用于当前单 Web 进程的 Daphne/ASGI 部署。不要直接配置多个 Web worker：任务注册表和串行队列是进程内的。未来多进程／多机部署应迁移至独立任务 worker 和共享队列。

答案快照持久化，但模型推理不是可恢复的持久化作业。关闭 Web 进程或重启电脑会中断执行与队列；重新读取会话时将无对应任务的活动记录标为未完成，保留正文并提示重试。为避免刚创建记录尚未注册任务的竞争，至少等待十秒才认定为孤立任务。模型错误和原有问答超时仍正常终止回答。

## 部署与回滚

1. 停止接受新回答并等待当前任务结束；备份 SQLite 数据库。
2. 使用项目 Python 环境运行 `python manage.py migrate`，应用 0025。
3. 重启单进程 ASGI Web；浏览器刷新一次以加载新版脚本。

回滚前停止 Web，将 queued/running 记录改为 incomplete 并记录服务回滚原因，再用本次代码运行 `python manage.py migrate kb 0024`，切回旧代码并重启。旧版本不理解 queued/running，不应直接带着活动状态降级。原文、文档索引和模型配置无需变更。

## 验证

- 152 项 Django 回归通过，含断开订阅后继续生成、显式停止、单会话重复提交、串行排队、取消排队任务、权限隔离、进程重启遗留状态。
- 20 项 Node 回归通过，含返回后轮询到完成、离开忽略旧响应、暂时失败重试与权限错误停止。
- 首页和检索页真实模板渲染与内联脚本语法检查通过。
- 真实本地 HTTP 首个心跳后断开，答案仍在约 8.8 秒内完整保存（55 字）。
- 浏览器实际执行提问、切换资料上传页面、后退；返回时显示生成进度，之后自动显示完整答案且发送按钮可用。

上述为任务生命周期验证，不代表复杂资料问答的事实准确率或性能验收通过。
