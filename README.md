# FOS·RAG 游乐设施工程知识库

FOS·RAG（页面名称为 SHDR RAG）用于从维护手册、工程图纸和业务记录中查证资料。例如，已知图号时，可以找出相关部件、业务表原始行和手册页。只知道要解决的问题时，可以用中文提问，再沿回答的引用核对原文。设备模型和运维工作台分别用于按实物位置追踪部件，以及查询工单、日志和停机事件。

## 本地启动

已有站点的用户可直接登录。首次部署在项目根目录操作，使用 Python 3.13 和 [requirements.txt](requirements.txt) 安装依赖。以下为 macOS / Linux 本地开发步骤。

```sh
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
test -f .env || cp .env.example .env
# 编辑 .env，填写本部署的 DJANGO_SECRET_KEY 以及实际服务地址
python manage.py migrate
python manage.py createsuperuser
python manage.py check
python manage.py runserver 127.0.0.1:8000 --noreload
```

打开 [本机首页](http://127.0.0.1:8000/)，用刚创建的账号进入「站点配置」。先为回答模型和向量服务填写实际的 Base URL、模型 ID、认证所需的密钥，以及向量服务的输出维度，分别保存并测试。若回答服务在局域网或云端，还需开启远程回答许可。处理 PDF 时，在另一个已激活环境的终端运行 `mineru-api --host 127.0.0.1 --port 8888`，或在设置中指定已部署的 MinerU 4.0.x／4.1.x 服务（应用读取服务端版本号自动选择协议，无需开关）。

Windows 可在准备好 Python 3.13 和本机配置后运行 [start_all.bat](start_all.bat)。脚本准备虚拟环境、迁移数据库、收集静态文件并启动 MinerU 与网站。首次建管理员账号可在项目目录运行 `.venv\Scripts\python.exe manage.py createsuperuser`。从旧版升级时，先执行 `.venv\Scripts\python.exe -m pip install -r requirements.txt` 更新依赖；PDF 解析服务用 MinerU 4.0.12 或 4.1.x 均可，两者协议不同，由应用自动识别。回答模型、向量服务和定时采集器各自配置、启动。

## 账号与权限

| 身份 | 可做的事 |
| --- | --- |
| 普通用户 | 注册或登录，在知识库问答和综合搜索中使用「通用」及本人所属部门（可多个）的资料，查看已确认图谱知识，使用设备模型。可创建并管理「个人（仅本人）」知识库，上传、检索自己的资料；点击侧栏账号名进入「个人信息」，可更新姓名、联系邮箱或修改密码。 |
| 部门管理员 | 在本人所属的**任一**部门建库、上传、维护追踪表、配置采集、审核图谱，在「用户管理」中添加和管理这些部门的成员。 |
| 站点管理员 | 跨部门管理共享资料和账号，登记、重命名部门，为成员分配部门（可多个）与角色，使用站点配置、检索评估、运行日志及相应 Django 后台权限。 |
| 运维工作台使用者 | 站点管理员和 Django「运维数据工作台」组成员可查运维数据。需要给普通账号单独开放时，在 Django 后台创建或选取该组并添加成员。 |

登录页为 `/accounts/login/`，自助注册页为 `/accounts/register/`，Django 管理后台为 `/admin/`。新注册账号归入「通用」，管理员在 `/accounts/users/` 分配实际部门。库的部门决定资料可见范围。顶层文件夹调整部门时，子库跟随更新。管理权限与问答范围分开，日常问答按当前账号的「通用＋本人全部部门＋本人个人库」检索。个人库由创建者独占，其他账号（包括管理员）不能查看、检索或管理；文档、图谱、追踪表和报告下载均遵守此范围，个人报告下载链接也需要创建者登录。已有库继续使用原有通用或部门范围。

> **一个账号可以属于多个部门**。「通用」本身也是一个部门，默认分配给**全部**账号且不可取消：它提供公共资料的阅读范围，所以删不掉也不需手动勾。其它部门在「用户管理」的行内展开「所属部门」勾选，可任勾选多个，可见范围是它们的并集（问答、搜索、追踪表都跟着走）。
> 每项归属有一个「主部门」（行内左侧下拉）：新建知识库与个人库的默认归属按它判定，而「通用」资料的**维护权**也只给主部门就是「通用」的账号（全局管理员不限）。否则人人默认挂着「通用」，等于把公共库的编辑权发给全站。
> 部门管理员能看到自己任一部门的成员，也只能把成员放到自己所属的部门里；新部门仍在「部门」板块先登记，再从勾选里选。

## 文件上传与入库

### 选择目标库并提交文件

1. 登录后打开「知识库中心」（Knowledge Library，`/kb/manage/`）。新资料先点「＋ 新建手册库」，填写名称、可选描述和访问范围。普通用户默认创建「个人（仅本人）」库；管理员还可选择部门或通用范围（属于多个部门时，部门下拉里可选其中任何一个）。名称适合用设备或资料集名称，描述可以补充别名、型号或用途，供问答选库时参考。
2. 在目标库点「知识库主页」，可在页首的「编辑知识库」更改名称、描述和访问范围。连接知识库仅在「按关联群」气泡视图中操作。可以多选文件、点「选择整个文件夹」，也可以直接拖入文件夹。页面递归列出支持的文件，同一批待传队列按文件名和大小去重，所有文件归入已选库。
3. 对图纸或扫描 PDF，按需勾选「图纸 / 扫描件（整页视觉入库）」。点「开始上传」，等浏览器把队列逐项提交完。文件进入服务器队列后，可以离开页面。Excel、Word 与邮件和其它文档一样保存在当前库，并可使用追踪表 AI 提炼。
4. 回到库详情看文档列表。点已完成的文件名可查看含标题、表格和插图的正文，也可更新文档描述或删除文档。库本身可改名、调整描述或删除。删除时会清理所涉文档和索引。新建的顶层手册库是一个文件夹，每份手册或照片自动获得一个继承访问范围的子库及独立向量集合。已有的独立文档库仍可直接接收资料。

> **访问范围与「只读」**：「通用」库对**所有部门**开放——文档正文、追踪表（可核对记录并导出 Excel）、采集参数趋势分析、综合搜索与问答都可用；但上传、改名、删除与追踪表字段配置等写操作由**全局管理员**维护。其它部门账号在「知识库中心」页只看得到自己能管的库（手册库 / 业务数据），能查阅但改不了的公共库列在页面底部的「公共知识库」列表里，点库名即可进入查阅（本部门库本部门管理员可写；「个人」库仅创建者可见）。

### 各种文件如何处理

| 输入 | 处理方式 | 到哪里看结果 |
| --- | --- | --- |
| PDF 手册、扫描件、图纸 | MinerU 提取 Markdown、插图和可用的页码及版面坐标。默认建文本索引。有原生图文向量服务时，还会索引符合条件的插图。额外勾选整页视觉，可将有版面数据的 PDF 页转成图像参与检索。 | 文档列表、综合搜索、问答引用。有定位信息时可打开原 PDF 页查看标框。 |
| Markdown（`.md`、`.markdown`）、`.txt` | 按 UTF-8 读取，直接分块、向量化，可用于先测试文本问答。 | 文档正文、命中片段及所在章节。 |
| 照片（`.jpg`、`.jpeg`、`.png`、`.webp`） | 校正方向、缩放保存，从文件名生成检索文字。配置原生图文向量服务后可按画面内容召回。 | 原图、综合搜索的图片命中、问答中的图片候选。 |
| 表格（`.csv`、`.tsv`、`.xlsx`、`.xlsm`） | 保存原文件，逐工作表读取为表格正文，保留说明、原始行号、日期和公式文本，再建立文档索引。旧版 `.xls` 先另存为 `.xlsx`。 | 当前库文档列表、综合搜索、问答；启用追踪表后可 AI 提炼。 |
| Word（`.docx`） | 离线读取段落、标题、表格和嵌入图片，再建立文档索引。旧版 `.doc` 先另存为 `.docx`。 | 当前库文档正文、综合搜索、问答及追踪表提炼。 |
| 邮件记录（`.eml`、`.msg`） | 离线读取主题、发件人、收件人、日期、正文和附件名称。邮件附件不作为独立文件自动入库。仅含 RTF 正文的 MSG 需另存为 EML。 | 当前库文档正文、综合搜索、问答及追踪表提炼。 |

表格、Word 与邮件文件上限为 25 MiB，提取正文最多 500 万字符；超限时明确报错，保留原文件供重试。表格保留所有原始行，不再自动转换成另一张业务数据卡片。此前专用结构化导入的数据继续支持业务键联查；历史导入未保存原始文件，需要按文档处理时请重新上传原件。

### 处理进度与失败恢复

手册依次经历「排队中 → OCR 或读取 → 向量化 → 已完成」。服务器保留供阅读的文档正文，另将表格还原为可检索的行列文本，按章节分块并保留相邻重叠。切块大小和重叠可在设置中调整，示例配置分别为 800 和 150 字符。文本向量分批写入 Chroma，同批片段也写入本地 SQLite 关键词索引。两者分别用于按语义找资料和按编号、术语找原句。

同一主机的入库任务按队列逐份处理。若失败，先看文档旁的错误信息，修好服务后点「重试（继续进度）」。系统复用已经保存的解析结果及成功写入的向量批次。ASGI 服务重启后会重新排队处理中断的文档。已完成的 PDF 也可在列表开启或关闭整页视觉模式，补建需要原 PDF、版面数据及支持图像的向量服务。[上传队列与恢复机制](docs/upload-reliability.md)

## 模型与解析接口

站点管理员在 `/kb/settings/` 分别配置回答、向量、重排、解析服务和检索参数，可保存分类预设、切换并测试。模型名称填写服务实际暴露的 ID。地址、密钥、模型及数值配置优先采用已保存的站点值，空值回退至部署环境。[`.env.example`](.env.example) 列出了主要变量。

| 服务及配置项 | 站点如何调用 | 何时需要 |
| --- | --- | --- |
| 回答模型（`LLM_BASE_URL`、`LLM_MODEL`、`LLM_API_KEY`） | OpenAI 兼容的 `POST {base}/chat/completions`，请求包含 `model`、`messages`。手册问答需要工具调用和流式响应。开启「支持图片输入（视觉）」后，服务还要能接收图像内容。 | 生成回答、规划与核实、文档台账抽取、图谱抽取和 AI 采集助手。问答可发送问题、近期上下文、命中的原文，启用视觉时可能发送图片。 |
| 文本向量（`EMBEDDING_BASE_URL`、`EMBEDDING_MODEL`、`EMBEDDING_DIMENSIONS`、`EMBEDDING_API_KEY`） | OpenAI 兼容的 `POST {base}/embeddings`，传入 `model`、`input` 和配置的 `dimensions`，读取 `data[].embedding`。配置维度应与服务实际输出一致。 | 上传时把片段转成向量，提问时把查询转到同一向量空间。两个阶段需使用匹配的配置。 |
| 图文向量（可选，复用向量配置） | 本地 WeMM 与 EmbeddingGemma 2 均调用 `POST {base}/embed`（`inputs`、`dimension`），模型名含 `wemm` 或 `embeddinggemma` 且 Base URL 不以 `/v1` 结尾时分别选用对应客户端。WeMM 保留原有列表式 `content`；Gemma 使用带媒体占位符的字典式 `content`，文本查询/语料分别使用 `SearchQuery` / `Document` 前缀。Gemma 维度支持 128、256、512、768。此前用旧适配器建立的 Gemma 索引须重建，避免混用未加前缀的旧向量；WeMM 索引无需因此重建。 | 按描述找照片、手册插图及整页图纸需要图文索引。普通 `/embeddings` 配置用于文本。回答模型的视觉开关另行控制是否让模型看图复核。 |
| 重排序（可选，`RERANK_BASE_URL`、`RERANK_MODEL`、`RERANK_API_KEY`） | `POST {base}/rerank`，传入 `query`、候选 `documents`、模型 ID 和可选 `top_n`，读取 `results` 中的 `index` 和 `relevance_score`。 | 在初次检索之后给候选原文排序。在设置页启用。关闭或请求失败时使用已有的融合排名。 |
| PDF 解析（`MINERU_API_BASE`、`MINERU_BACKEND`、可选 `MINERU_API_KEY`） | 支持 MinerU 4.0.x 与 4.1.x，Base URL 填服务根地址，协议按 `/v1/health` 报告的版本号自动选择。**4.0.x File API**：小文件随 `POST /v1/file_parse` 内联提交，大文件经 `/v1/uploads` 登记、传输并取得文件 ID，产物从 `GET /v1/tasks/{id}/result` 的 JSON 里读。**4.1.x Tasks API**：`POST /v1/tasks` 声明文件（`output_formats:["default"]`），再 `PUT` 响应里的上传链接传字节，产物从 `files[].result_url` 下载 `result.zip`，取出 `markdown.md` 与 `structured_content.json`。两路产物在 `kb/pipeline.py` 归一为同一形状，3.x 的表单接口不受支持。 | 仅 PDF 走此流程。原始 PDF 会发送到所配置的解析服务。 |

**如何填地址。** 例如回答服务的完整端点是 `http://127.0.0.1:1234/v1/chat/completions`，那么 Base URL 填 `http://127.0.0.1:1234/v1`，接口路径由应用追加。MinerU 的默认地址为 `http://localhost:8888`。需要认证时按对应服务填写密钥。

**本机、局域网与远程。** 回答模型使用非本机地址时，开启「允许远程回答 API」，局域网地址也适用。「允许全部远程／局域网 API」覆盖上述回答、向量、重排和 OCR 服务。使用 `FOS_LOCAL_ONLY=1` 部署时，网络限制按已许可的主机和端口放行。全局设置里仅允许回答模型远程时，向量、重排、OCR 可继续留在本机。运维工作台 AI 另有本机模型要求。[远程 API 开关说明](docs/remote-answer-api.md)

**如何判断接通。** 保存后点每项的「测试」或「一键全部测试」。回答测试发送一次非流式提问并检查是否完整回复 `OK`，向量测试实际生成向量，重排测试比较相关与无关文本。MinerU 测试读 `/v1/health`（其次 `/v1/models`）的版本号，回报将要使用的协议，例如「MinerU 4.1.7 可达，PDF 将按 Tasks API（4.1） 解析」；只有根 `/health` 的 3.x 服务直接判为不支持，报不出版本号时算连通但给出提示。若探针结果与处理情况不同，用一份小 PDF 确认。工具调用、流式输出和片段引用可用上面的培训样例验证，PDF 页码和标框要在 PDF 引用中核对。

## 一次问答如何完成

对话不指定默认知识库，尚未上传资料时也能正常聊天。EnGenie 根据当前问题和已获得的上下文决定是否检索，需要新资料时自行选择有权访问的来源；会话不会因提到某个库而绑定它。

登录后可在首页快速提问，或从导航「AI 助手」、右下角气泡、`/kb/ask/` 打开带历史会话的助手。问题写出文件名、设备名或编号更容易找准资料。例如，“在《培训样例》中找到 DEMO-01 的登记位置，附原文”。

1. **确定从哪份资料找。** 系统先用问题匹配可见库名、描述和文件名。明确命中的资料成为本轮默认范围，追问可沿用会话范围。助手也可以继续检索当前用户可见的其他库。进入单份文档库时查该文档，选文件夹时合并子库结果。
2. **按问题挑证据。** 语义检索按意思找原文，关键词检索补足型号、图号、缩写等精确匹配。系统按各路名次融合去重（RRF），也可合入图谱关联的手册片段，再按配置重排。条件或表格跨块时，助手可补读相邻片段、指定章节。问整本手册概览时会读取目录和各章代表片段。问已登记字段可查追踪表，问已审核的属性或关系可查图谱，找图片则先召回候选，有视觉能力时再逐张复核。
3. **形成和核对答案。** 普通模式通过 SSE 将进度和回答分段送到页面。可选的「问答管线增强（规划 + 核实）」用同一回答模型先理解问题，再对照本轮证据核实草稿，并检查引用是否仍可见、内容是否有效。图谱事实和整本概览也会触发核对。证据不足时会提示缺少依据，无法验证的概览可回退到可核实的原文章节标题。
4. **打开出处。** 点击回答下方的引用卡查看文件、章节与原文片段。有页码和区域坐标的 PDF 会在证据面板中显示原页并标出位置。缺少版面信息时可看原文切片或文档正文。图谱引用可回到已审核的事实，核对其条件、来源段落或表格原始行。
5. **继续追问或导出。** 单说“列成表格”会在聊天里显示 Markdown 表格。明确要求统计、画图或下载时，普通模式可在浏览器的 Pyodide 环境运行 Python，回传执行结果，显示图表并提供 Excel、CSV 或 PNG 下载。生成图表和文件时请保持聊天页面打开，等待下载按钮出现。增强模式及图谱事实导出使用核实后的表格生成 CSV。

**会话恢复。** 可新建、切换、删除自己的会话，或主动停止回答。刷新、收起面板、切到其他页面后，已提交的回答可在 Web 进程中继续生成，返回时恢复正文、出处和未读提醒。服务提供 Token 用量时，对话页还显示本次会话累计输入、输出及单次调用峰值。同一会话一次只处理一个回答，当前部署由单个 Web 进程串行执行生成任务。服务重启后，再次读取会话时会把中断的任务标为未完成，此时可重新提问。追问只携带有限的近期完整问答，未核实的历史回答不会作为新的事实依据。[助手使用说明](docs/assistant-widget.md) · [后台回答与恢复](docs/background-answers.md)

## 自动更新知识库

当资料来自每日接口或动态网页时，从「知识库中心 → 自主数据引擎」(`/kb/feeds/`) 创建数据源，选用已有库或建立归到「业务数据」的新库。采集的记录整批成功后直接写入追踪表，每行带采集时间、来源 ID 和业务字段。这些记录可在追踪表查看并导出，无需逐条 OCR 或生成文档向量。普通问答可查台账，工具从选定范围最近更新的 200 行里返回最多 20 条匹配。要统计完整历史，请使用追踪表导出。增强问答还需要可核实的原文或图谱证据。

| 接入方式 | 操作 |
| --- | --- |
| 定时拉取 | 对已经提供 `fos-rag-feed/v1` 的 HTTP 接口，填写拉取地址、认证信息、五字段 cron 和时区。如设为 `0 8 * * *`、`Asia/Shanghai`，表示上海时间每天 08:00 执行。可先手动运行，核对本次采集结果。 |
| 外部脚本推送 | 在数据源页生成专用令牌，外部任务以 Bearer 认证向页面给出的 `POST /kb/api/feeds/<feed_id>/ingest/` 提交 JSON。每条记录使用稳定 `id`，同一批重送时复用 `batch_id`。页面提供运行状态及连接器工具包。 |
| AI 生成连接器 | 打开 `/kb/feeds/builder/`，提供网址、要采的字段、记录标识和频率。例如“从这个页面每天采集设备编号和状态”。助手可探测 JSON 或用浏览器操作动态网页，试取真实样本、校验字段，展示数据预览。可继续对话修正，点击「确认数据并开始自动更新」才启用并首次入库。已批准的任务可再次编辑、更新凭据或下载脚本。 |
| 命令行建任务 | `LIGHTBOARD_TOKEN=… python manage.py build_feed "每天13点拉 …/lightboard/board/ 的每车当前里程" --url … --token-env LIGHTBOARD_TOKEN --private --wait 900`，看过真实样例后再加 `--approve`（或事后 `--job <任务号> --approve`）。密钥只从环境变量读；权限、内网开关、凭据与批准规则与页面完全相同，因为两者调用同一个 `kb/collector_api`。 |

写入方式与接入方式独立。**追加历史**（`append`，默认）保留每次成功采集的观察值，适合趋势对比。**更新当前记录**（`upsert`）按同一数据源的稳定 ID 更新，适合当前设备清单。单次漏采的条目会保留，已完成批次用相同 ID 重送不会再追加一遍。

定时拉取需要独立运行调度器。激活项目环境后，在另一终端运行 `python manage.py run_feed_scheduler --interval 30`，或由系统计划任务定期执行 `python manage.py sync_feeds --due`。网页采集还需要可用的 Chromium 或 Edge，可通过 `FOS_BROWSER_EXECUTABLE` 指定现有浏览器，或执行 `python -m playwright install chromium` 安装。数据源页可检查最近调度、运行结果并暂停或恢复任务。[采集配置、认证与故障排查](docs/knowledge-feeds.md) · [批次协议](docs/schemas/knowledge-feed-v1.schema.json) · [示例数据](scripts/connectors/example_feed.json)

## 知识图谱

在 `/kb/graph/` 可以把“手册某处写了什么”整理为带适用条件、可重复引用的知识。它适合处理同一部件在不同条件下有不同取值，或要从设备编号追到图号和原始记录的情况。

1. **选资料和主题。** 库管理员选择已完成的文档，填写要抽取的主题并开始构建。系统检索相关段落，按需补读相邻内容，结合原始表格行列生成候选。页面显示任务进度和批次记录。
2. **逐条对原文。** 在对象树沿“对象 → 属性 → 分类项 → 子属性”展开，检查数值、单位、条件、引文及可用的 PDF 圈注，确认或拒绝每条内容。新资料可向同一对象追加分支，跨库追加需明确选择目标。不同标准或版本的取值分别保留。
3. **查询已确认内容。** 读者可以浏览已确认且来源仍有效的知识，在助手中按对象、属性或编号提问，由事实引用回查原文。权限变化、数据集换版或撤回确认会影响该条知识的检索资格。

在「高级工具」可从已归库的业务表补建设备、部件和图纸的关系候选，或给关系补充手册引文。在「筛选与历史」选择批次后，展开「旧版关系图与历史记录」可查看关系连线。补充原文后该关系需重新审核。原始行保留文件、工作表和行号，便于核实为何两个编号被关联。[知识图谱操作说明](docs/knowledge-graph.md) · [分层知识与审核规则](docs/knowledge-graph-hierarchy.md)

## 设备模型与车辆部件追踪

**通用设备档案**位于 `/tools/equipment-models/`。登录后选「新建设备」，录入设备和部件，填写固定编号、上级部件、图号和说明，即可建立部件树。打开某个部件可登记学习笔记和追踪记录，点击图号可查有权查看的资料并定位 PDF。共享设备可创建学习副本。个人档案按当前浏览器和 RAG 账号保存，跨浏览器或跨实例使用时先导出模型 JSON，再到目标目录导入。

通用档案的交换格式是 `shdr-equipment-model` v1，单文件上限 2 MB、2,000 个部件、4,000 条记录。管理员将通过校验的清单放入 `data/equipment_models/*.json` 即可发布共享目录。通用档案使用部件树，已接入专用三维查看器的设备才会出现对应入口。[设备模型格式、完整样例与查看器接入](vehicle_tracker/EQUIPMENT_MODELS.md)

**七个小矮人矿山车**使用专用三维工作台 `/tools/equipment-models/sdmt/`，原书签 `/tools/vehicle-tracker` 仍可用。一组追踪记录可以按下面的顺序核对。

1. 用「项目」下拉框选已有项目，或在「项目管理」中新建。用结构树、位置码搜索或点击三维示意图定位部件。可以聚焦某个部件、切换视角、透视车底或隔离所选部件。
2. 点「导入追踪表」，选择 Excel、CSV 或 TSV，核对工作表和列映射。系统按工单号、序列号和图号组合识别重复记录。勾选记录和目标部件后点「绑定到所选部件」，也可筛选未绑定记录或解除绑定。
3. 在部件详情查看记录、填写核对备注、加附件或查履历。例如可为销轴登记年度检验或更换工单，填写工单号和序列号。在「参考图标注」上传照片，用热点指向对应部件。点图号可标出对应的全部部件位置、筛选追踪记录或查知识库文档。导入运维数据后，还可读取 QAQC/MRB 记录、工单、作业计划及工单 PDF。QAQC/MRB 读取导入的本地快照，工单、作业计划和 PDF 使用运维数据工作台的 Maximo 只读连接，无需另行启动工程工具箱服务。
4. 需要解释部件、核对记录或了解操作时可打开「车辆 AI」。它通过站点回答模型分析当前选择、项目摘要、有限的记录样本和按需查询的 QAQC 数据，返回可定位的部件。绑定关系仍由使用者确认。

车辆项目、参考图、附件和绑定记录保存在当前浏览器的 IndexedDB。**导出 CSV** 用于交换核对表，**完整备份**导出的 JSON 用于在另一浏览器恢复项目副本。清理浏览器站点数据前，应先导出需要保留的项目。

## 运维数据工作台

从 `/tools/operations/` 进入，选择数据源和查询类型，填写时间范围、设备或业务编号，运行只读查询后可打开结果详情。手动表单可独立使用。实时查询需要运维访问权限、已配置的数据源和可达的服务。

| 来源 | 可以查什么 | 如何继续核对 |
| --- | --- | --- |
| Maximo | 通过服务器端只读 Oracle 连接筛选工单、作业计划，查看指定编号的详情。工单详情分为关键信息、描述、计划时间、工时、任务卡片和状态履历。 | 从作业计划查看关联工单，打开中文或英文工单、作业计划 PDF；预览失败时可新窗口打开或下载原 PDF。 |
| Splunk | 在预设的 Apex 日志索引和时间窗口内，按设备、景点及界面支持的字段筛选事件。 | 在结果中查看事件时间及日志明细，缩小时间窗继续查询。 |
| Downtime | 从已导入快照或实时 Maximo 查询停机事件、统计图表（每日趋势、景点、停机代码、分类、设备、日期×景点）和设备故障履历。 | 与上一等长周期对比；点击图表筛选事件表，打开停机事件后按故障时段联查 Splunk，可调整前后缓冲分钟数。 |

列表结果显示服务器统计的精确总数，可分批读取，「导出全部 CSV」单次最多 5000 行。

「运维 AI」接受自然语言问题，例如“查某景点在指定日期的停机事件”。拿到事件后，可在详情中联查对应时段的日志。它用**本机回环地址的回答模型**选择最多三项允许的查询，由服务器实际执行，再根据返回结果作答。页面列出查询操作、参数、时间及结果，可区分没有匹配、来源连接失败和快照覆盖不足。此模块的模型限制独立于站点的远程回答许可。

首次接入时，准备已配置的工程工具箱和 Apex Portal 目录，在项目根目录执行以下命令，将路径替换为实际位置。重新导入可刷新停机与 QAQC 快照。工具箱目录只在导入时读取。

```sh
python -m operations_workbench.import_sources \
  --toolbox "/path/to/engineering-toolbox" \
  --apex "/path/to/apex-portal"
```

本机连接配置、JDBC 运行资料和快照默认放在 `.runtime/operations-workbench/`。Web 服务使用其他运行目录时可设置 `OPERATIONS_RUNTIME_DIR`。实际 Oracle 和 Splunk 地址需从部署机可达。[运维数据工作台接入说明](operations_workbench/README.md)

## 运行与维护

**运行日志与检索评估。** 站点管理员在 `/dashboard/` 可看用户、文档、向量块、会话、当日活跃、近 14 天问答趋势、各库处理状态和最近活动。在 `/kb/eval/` 添加回归问题，填写期望的来源文件名或片段关键词，执行后查看前五条结果、命中渠道及排名。两项都填时需同一条结果同时满足。Hit@1、Hit@3 分别表示有期望的题中，满足期望条件的片段出现在第一名、前三名的比例。它们衡量找资料的效果，适合在换模型、调检索参数前后比较。终端入口为 `python manage.py eval_retrieval`。

| 遇到的现象 | 先检查什么 |
| --- | --- |
| 文件已提交，问答还找不到 | 回目标库看文档是否已完成、片段数及错误信息。PDF 先查 MinerU，再查向量服务。Excel、Word 和邮件可先打开解析正文核对内容，再检查索引状态。 |
| 问的设备正确，引用来自另一本手册 | 在问题中给出设备编号或完整文件名。打开引用核对版本、章节与条件。管理员可补全库名和文档描述，或在评估页加一条带期望出处的回归题。 |
| 想按图像内容搜，结果只有文字 | 检查该库入库时是否使用支持图文的原生向量接口。整页 PDF 还需开启整页视觉并保有版面数据。需要模型判读图片时，再检查回答模型能否接收图片以及站点视觉开关。 |
| 提示向量模型配置变化或维度不符 | 检查端点、模型 ID、返回维度与建库配置。即使两个模型的维度相同，其向量也不能混用。切换向量空间时先备份并暂停该库检索和入库，运行 `python manage.py reindex_clean --dry-run` 查看范围。确认后，用实际**文档库**标识替换 `DOC_LIBRARY_SLUG`，执行 `python manage.py reindex_clean --kb DOC_LIBRARY_SLUG`。该命令从已保存正文重建索引，完成后重启 Web。 |
| 已保存采集计划，但没有新记录 | 在自动更新页检查是否启用、最近一次调度及运行详情。拉取方式检查调度进程、时区、来源凭据。推送方式检查外部任务、令牌和批次状态。 |

**数据保存在哪里。** `db.sqlite3` 保存账号、库配置、解析正文、会话消息、业务表、追踪行和图谱审核记录。`media/documents/` 保存上传的手册与照片原件，`data/chroma/` 和 `data/keyword.db` 保存两种检索索引，`data/doc_images/`、`data/doc_meta/` 保存图片和定位资料。迁移或重建前，停止相关写入并一并备份数据库、`media/`、`data/` 和部署私有配置。有自动采集凭据时须保留 `data/secrets/feed-credentials.key`。设备个人档案和车辆项目另用页面导出备份。
